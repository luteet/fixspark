# CLAUDE.md — Fix Spark

## Что это за проект

Статическая вёрстка (HTML + SCSS + vanilla JS) для сайта локальной службы ремонта бытовой
техники **Fix Spark** (San Diego County). Дизайна «отдельно от кода» нет: вёрстка сразу
делается с дизайном (design-driven layout), а дизайн-система описана как токены в SCSS.

**Текущий рабочий каталог: `layout/`.** Только в нём ведётся работа.
Всё остальное — контекст, читать можно, менять — нет (см. «Границы работ»).

В будущем поверх этой вёрстки будет собрана тема WordPress. Поэтому разметка и стили
должны оставаться переносимыми: компонентные классы, отсутствие завязок на «одну страницу»,
никаких абсолютных путей и никакой логики, привязанной к конкретному месту в документе.

## Карта репозитория

| Путь | Роль | Можно менять |
| --- | --- | --- |
| `layout/` | сама вёрстка, Gulp-сборка | да (основная зона) |
| `DESIGN.md` | дизайн-спека: палитра, типографика, компоненты, правила | только по прямому запросу |
| `prototype/` | экспорт исходного прототипа (`index.html`, `DESIGN-HANDOFF.md`, `DESIGN-MANIFEST.json`, видео, лого) | нет |
| `design/` | PDF-макеты | нет |
| `images/` | исходные картинки/баннеры для контента | нет |

`layout/dist/` и `layout/node_modules/` — генерируемые, в git не нужны, руками не править.

Источники истины при конфликте приоритетов:
1. `DESIGN.md` — правила дизайн-системы (цвета, размеры, состояния, запреты).
2. `layout/app/scss/global.scss` — единственное место с реальными hex-значениями токенов.
3. `layout/app/ui-kit.html` — витрина компонентов, живая документация системы.
4. `prototype/` + `DESIGN-HANDOFF.md` — визуальный контракт (пиксели и поведение прототипа).

## Стек и сборка

Gulp 5 на ESM (`"type": "module"`), сборщика модулей нет — JS минифицируется как есть.

- SCSS → `dart-sass` → PostCSS (`postcss-sort-media-queries`, `autoprefixer`, `cssnano`)
  → `dist/css/style.min.css`
- HTML → `gulp-file-include` (`@@include`) → `gulp-beautify` (табы) → `dist/`
- JS → `gulp-uglify` → `dist/js/`
- Изображения → `sharp` (сжатие JPG/PNG + генерация `webp`/`avif`)
- Шрифты → `wawoff2` (TTF → WOFF2)
- SVG-иконки → `gulp-svg-sprite` (`dist/img/sprites.svg`)
- Dev-сервер → `browser-sync`

Ключевые файлы сборки: `layout/gulpfile.js`, `layout/gulp/config.js`,
`layout/gulp/libs.js`, утилиты `layout/gulp/utilities/*.js`.

### Команды

Все команды выполняются из `layout/`:

```bash
cd layout && npm install     # один раз
cd layout && npx gulp        # сборка + dev-сервер (без открытия браузера)
cd layout && npx gulp open   # сборка + сервер + открыть браузер
cd layout && npx gulp build  # чистая сборка всех ассетов
cd layout && npx gulp clean  # удалить dist/
cd layout && npx gulp zip    # собрать архив dist-папки
cd layout && npx gulp folder # выгрузить собранный проект в папку <name>
```

`<name>` берётся из `package.json` (`fixspark`); если поле пустое, задачи падают
с ошибкой `The project name field is empty`.

Порядок `build` в `gulpfile.js`: `cleanOrphans` + `libsStyles` + `scss` + `js` +
`libsScripts` → `sprites` → `fonts` → `images` → `html` + `htmlComponents`.

`cleanOrphans` удаляет из `dist/` файлы, у которых больше нет источника в `app/`.
Следствие: удаление исходника автоматически чистит артефакты.

## Структура `layout/app`

```text
app/
├── index.html              # главная страница
├── ui-kit.html             # витрина дизайн-системы (отдельная страница сборки)
├── html/
│   ├── header.html         # <head> + <header> + .skip-link + .wrapper
│   └── footer.html         # <footer> + .sticky-bar + скрипты + </body>
├── fonts/                  # TTF (в WOFF2 конвертируются сборкой)
├── img/
│   ├── sprites/*.svg       # иконки для спрайта
│   └── *.mp4|jpg|png       # медиа
├── js/main.js              # единственный собственный скрипт
└── scss/
    ├── style.scss          # точка входа: только @forward-директивы
    ├── libs.scss           # ГЕНЕРИРУЕТСЯ из gulp/libs.js, вручную не править
    ├── reset.scss          # собственный reset поверх modern-normalize
    ├── global.scss         # :root-токены, базовая типографика, .container, .wrapper
    ├── utilities.scss      # .visible-on-mobile/.desktop, .visually-hidden, .image-aspect-ratio
    ├── mixin.scss          # @mixin font()
    ├── components/         # переиспользуемые блоки
    └── pages/
        ├── index/*.scss    # по файлу на секцию главной
        └── ui-kit/*.scss
```

Страница собирается из партиалов так:

```html
@@include("html/header.html", {"title": "...", "description": "..."})

<main class="main" id="main">
  ...
</main>

@@include("html/footer.html")
```

`header.html`/`footer.html` содержат весь каркас документа, поэтому новые страницы
начинаются с этих двух включений, а не с `<!DOCTYPE html>`.
Параметр `@@version` = `Date.now()` (кэш-бастинг для CSS/JS) подставляется сборкой.

## Правила SCSS

1. **Новый файл стилей не подключается руками.** При создании `app/scss/**/*.scss`
   (имя не начинается с `-`) вотчер добавляет в `style.scss` строку
   `// @forward "путь";` — **закомментированную**, перед маркером `// new`. То есть после
   создания файла нужно снять `//` (при повторном событии `add` вотчер раскомментирует
   сам, но полагаться на это не стоит). При удалении файла вотчер, наоборот, комментарий
   возвращает. Без запущенного вотчера директиву добавляй сам, в правильный раздел:
   `utilities` → `global` → `components/*` → `pages/*`.
2. **Маркер `// new` в конце `style.scss` не удалять** — это точка вставки вотчера.
3. Порядок каскада значим: `libs` → `reset` → `utilities` → `global` → `components` → `pages`.
4. **Цвета, отступы, радиусы, тени, типографика — только через `var(--*)` из `global.scss`.**
   Новых hex вне `global.scss` не бывает. Нужного токена нет — берётся ближайший
   существующий, а не изобретается новый.
5. Вложенность — `&__element` / `&--modifier` (BEM-подобная нотация), состояния —
   `&.is-*` или модификатор блока (`header--scrolled`, `header--menu-open`,
   `is-mobile-nav-active`).
6. Один файл = один блок/секция. Файлы компонентов — `.block { &__el {} }`,
   файлы секций — `.section-name { &__el {} }`.
7. **Медиа-запросы пишутся внутри элемента/блока, а не отдельным блоком в конце файла.**
   `&` в медиа-запросе продолжает текущий селектор:
   `&__media { @media (max-width: 64rem) { display: none; } }` —
   а не `.services__media { … }` отдельной секцией ниже. Брейкпоинты — в `rem`
   (`64rem` = 1024px, `40rem` = 640px). Состояния наведения/активности держим
   в своих группах: `@media (min-width: 64rem)`, `@media (hover: hover) and (pointer: fine)`,
   `@media (prefers-reduced-motion: reduce)`. Порядок внутри элемента — от большего
   экрана к меньшему; итоговую сортировку делает `postcss-sort-media-queries`.
8. Отступы — табы; свойства группируются логическими блоками через пустую строку
   (см. существующие файлы, стиль соблюдаем).
9. `libs.scss` — артефакт: он собирается из `layout/gulp/libs.js` (`libsStyles`).
   Библиотеки подключаются только там, не копированием CSS в проект.

### Реальные брейкпоинты вёрстки

`1200px` — контейнер, `1024px` (сетки, gutter 20px), `900px` (мобильная навигация,
`sticky-bar`, каскад `booking`), `720px` (pricing), `640px`, `560px` (gutter 16px,
мобильные отступы секций). `MENU_BREAKPOINT = 900` в `main.js` должен совпадать
с CSS для навигации. В SCSS брейкпоинты записываются в `rem` (`1024px` = `64rem`,
`640px` = `40rem`); px остаются в токенах `global.scss` и в `main.js`.

## Дизайн-система (инварианты)

Палитра и роли — `DESIGN.md` + `:root` в `global.scss`. Главное, что нельзя нарушать:

- **Harbor Navy `--surface-dark` (#0B2A3C)** — hero, тёмные панели, футер.
- **Spark Amber `--accent` (#F2A93B)** — исключительно телефонный призыв («Call») и звёзды
  рейтинга. Не текст, не ссылка, не бордер, не большая заливка. Текст на amber — только `--accent-on` (navy).
- **Pacific Teal `--link` / `--icon` (#0F7C7A)** — ссылки и иконки **только на светлом**;
  единственная teal-заливка на странице — блок `business`.
- **Steel `--on-dark-muted` (#9DB8C9)** — только на тёмных поверхностях.
- Поверхности: 70% white/mist, ~15% teal, ~10% navy, ≤5% amber. Никаких новых оттенков,
  градиентов между brand-цветами и цветных теней.
- Тёмные секции идут через `data-theme="dark-surface"` — это переопределяет
  foreground/border-токены внутри блока. Ставить на секцию или на вложенную панель
  (как `booking__panel`), не на body.
- Глубина: flat → hairline (1px `--border`) → raised (`--elev-raised`). Тень —
  последнее средство, сначала hairline или смена поверхности.
- Типографика: `--font-display` (Plus Jakarta Sans, 600/700) для заголовков и цен,
  `--font-body` (Inter, 400/500/600) для текста. Размеры — только шаги `--text-*`;
  заголовки ≥32px обязаны иметь отрицательный трекинг. Цены — `tabular-nums`.
- Радиусы: `--radius-sm` (инпуты), `--radius-md` (кнопки), `--radius-lg` (карточки),
  `--radius-xl` (крупные панели), `--radius-pill`.
- Контролы: высота `--control-h` (48px), в `sticky-bar`/хэдере — 44px.
- Анимация: только `opacity`/`transform`, ≤200ms; учитывать `prefers-reduced-motion`
  (глобальный блок в `global.scss` уже это делает).

Перед изменением внешнего вида компонента сверяйся с `layout/app/ui-kit.html` и
`layout/app/scss/pages/ui-kit/ui-kit.scss`; при изменении токенов/компонента витрина
должна оставаться корректной.

## HTML и контент

- Семантика обязательна: `header`/`nav`/`main`/`section`/`footer`, `h1` один на страницу,
  заголовки без пропусков уровней, интерактив — `a`/`button`/`input`, а не `div` с `onclick`.
- Доступность: `aria-label` на иконочных кнопках, `aria-hidden="true"` + `focusable="false"`
  на декоративных SVG, `aria-expanded` у бургера (уже реализовано), `.skip-link`,
  `:focus-visible` не убирается.
- Ссылки-якоря соответствуют `id` секций: `#services`, `#pricing`, `#repairs`, `#areas`,
  `#faq`, `#book`, `#top`. Переименование `id` = правка навигации, футера и `main.js`.
- Контент — реальный, конкретный, «trade business», без маркетингового шума
  (см. «Do's and Don'ts» в `DESIGN.md`). Не заменять специфичный текст заглушками.
- У каждой услуги/кейса есть цена рядом с названием; если цены нет в брифе —
  ставится явный плейсхолдер `$—`, а не пропуск строки.
- Телефон `(619) 555-0142` / `tel:+16195550142` — везде одинаковый.
- Форма бронирования — демонстрационная: `main.js` перехватывает submit, показывает
  `#form-status` и ничего не отправляет. Реальную отправку/интеграцию не добавлять
  без явной задачи (это уйдёт в WordPress-этап).

## Иконки, изображения, шрифты

- Иконки: положить `*.svg` в `app/img/sprites/`, сборка сделает `sprites.svg`, где
  `stroke`/`fill` заменены на `currentColor`. В разметке:

```html
<svg width="18" height="18" aria-hidden="true" focusable="false">
  <use href="img/sprites.svg#phone" />
</svg>
```

  Цвет иконки задаётся через `color` родителя, размер — атрибутами `width`/`height`.
  Инлайновые path в компонентах не пишем.
- Изображения — в `app/img/`; сборка сама генерирует `webp`/`avif`. В разметке
  указывать `width`/`height` (для `.image-aspect-ratio` JS выставляет `--aspect-ratio`)
  и `loading="lazy"` ниже первого экрана.
- Шрифты: TTF в `app/fonts/`, `@font-face` — через `@mixin font()` в
  `components/fonts.scss`, только Inter (400/500/600) и Plus Jakarta Sans (600/700).
  Новый вес/семейство = новый файл в `app/fonts/` + `@font-face` + `preload` в `header.html`.

## JS

- Единственный собственный файл — `app/js/main.js` (ES-модуль, без сборщика, минифицируется).
- Используются `const`/`function`, `document.querySelector*`, `addEventListener`,
  `classList.toggle`; без jQuery и без фреймворков.
- Сторонние библиотеки — только через `layout/gulp/libs.js`: раскомментировать/добавить
  путь из `node_modules`, затем `npx gulp build`. CSS библиотек автоматически попадает
  в `libs.scss`, JS — в `dist/js/libs.min.js` (подключается до `main.js`).
- Сейчас подключён Swiper (слайдер отзывов). Инициализация обёрнута в проверку
  `if (window.Swiper && ...)` — сохранять этот паттерн.
- Скрипты на страницу подключаются в `footer.html`, поэтому специфичный для страницы JS
  должен сам проверять наличие своих элементов.
- Пользовательские CSS-переменные, вычисляемые в JS: `--height-header`, `--vh`.

## Как добавлять

**Новая секция главной:** разметка — внутри `<main class="main">` в `index.html`
(`<section class="section ..." id="...">` с `.container`, при чередовании — `section--alt`);
стили — новый файл `app/scss/pages/index/<name>.scss`; навигацию/футер обновить при
необходимости. Заголовок секции — через `.section-head` + `.eyebrow` + `.section-lead`.

**Новый компонент:** `app/scss/components/<name>.scss` с `.block`/`&__el`/`&--mod`,
разметка — BEM-классы в HTML, при необходимости добавить пример в `ui-kit.html`
(+ `pages/ui-kit/ui-kit.scss`, если нужны стили витрины).

**Новая страница:** `app/<page>.html` с двумя `@@include`; стили — `pages/<page>/*.scss`;
общие блоки не дублировать, а использовать существующие компоненты.

## Границы работ

- Не редактировать `layout/dist/**`, `layout/node_modules/**`, `layout/app/scss/libs.scss`
  (генерируемые).
- Не менять `DESIGN.md`, `prototype/**`, `design/**`, `images/**` без прямого запроса —
  это входные данные дизайна, а не код.
- Не добавлять `package.json`-зависимости без необходимости; проверка новых библиотек —
  через `gulp/libs.js`. Не менять `overrides` в `package.json` без причины.
- Не переводить контент сайта на другой язык и не менять бизнес-факты
  (цены, телефон, лицензия, гарантия) самостоятельно.
- Не «улучшать» дизайн: любое отклонение от `DESIGN.md` — это ошибка, а не инициатива.

## Проверка результата

- По умолчанию результат проверяется **только по коду**: `npx gulp build` без ошибок
  Sass/HTML, чтение сгенерированного CSS, разбор разметки и логики.
- **Скриншоты в браузере не делаем** (headless Chrome, `qlmanage`, dev-сервер ради
  визуальной проверки) — это лишний расход времени и токенов. Визуальную проверку
  выполняет пользователь сам.
- Визуальный анализ и скриншоты допускаются только по прямой просьбе пользователя
  проверить/проанализировать внешний вид.

## Чек-лист перед сдачей правки

1. `cd layout && npx gulp build` проходит без ошибок Sass/HTML.
2. Код проверен на отсутствие горизонтального скролла и переполнений на 360 / 768 /
   1024 / 1440 / 1920 (фиксированные ширины, `min-width`, абсолютное позиционирование);
   визуальная проверка в браузере — на стороне пользователя.
3. Мобильная навигация (бургер, Escape, закрытие по ссылке) и `sticky-bar` работают
   на `< 900px`; телефон и «Call» видны на каждом мобильном экране.
4. Фокус виден на всех интерактивных элементах; `prefers-reduced-motion` уважается.
5. Новые стили используют `var(--*)`; hex не появился вне `global.scss`.
6. Amber используется только для телефона/звёзд; teal — только на светлом; тёмных
   секций подряд нет.
7. `ui-kit.html` не сломан, если менялись токены или общие компоненты.
8. Цены отображаются с `tabular-nums`, названия услуг и цены стоят парой.
